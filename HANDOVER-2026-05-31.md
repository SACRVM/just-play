- `WaveformHeader.axaml.cs` — zwei neue StyledProperties:
  `BpmHint` (`double?`, default → 120), `EnergyHint` (`int?`, default → 6).
  Tick rechnet `beatPhase = (t/beatSec) % 1`, `beatEnv = exp(-phase·4.5)`

- Bindings: `BpmHint="{Binding Current.Bpm}"` + `EnergyHint="{Binding Current.Energy}"`

## Was du beim Start sehen solltest

1. App startet, du droppst einen Track.
2. **Sofort** sind Title/Artist/Duration in der Queue → Metadata-Pass.
3. **Nach ~2-10 Sekunden** (je nach Track-Länge) erscheint die BPM-Spalte
   für jeden Track in der Reihenfolge wie sie reinkamen → BPM-Analyse-Pass.
4. Beim Play: Waveform-Header lebt — vier Linien skalieren auf Bass/Mid/
   LowMid/Treble der Live-FFT, und sie pulsieren zusätzlich im Takt der
   analysierten BPM.

## Stolpersteine die ich vermute

- **BPM-Werte können daneben liegen** — BASS_FX detect bekanntlich oft
  die halbe oder doppelte BPM bei syncopierter Musik. Das ist Algorithmus-
  Realität, nicht Wiring. Wenn's für deine Test-Tracks zu oft danebenliegt,
  könnten wir die MinMax-Range tighten (Parameter im `BPMDecodeGet`-Call).
- **FFT-Bands optisch zu bass-lastig oder zu treble-still?** Die per-Band-
  Multipliers in `BassAudioEngine.GetFftBands` (4×/8×/14×/24×) sind visuell
  geschätzt auf EDM-ähnlichem Material. Wenn du sagst "treble braucht
  weniger" oder "bass übersteuert", sind das die vier Stellschrauben.
- **WaveformEnabled=false stoppt Animation nicht** — das Element wird
  unsichtbar (`IsVisible=false`), aber der DispatcherTimer im Code-Behind
  läuft weiter. CPU-Last, nicht visuelle Bug. Wenn dich das stört, ergänzen
  wir ein Stop bei `OnDetachedFromVisualTree` plus IsVisible-Subscription.
- **Erst-Analyse-Pass bei vielen Files dauert** — seriell durch alle
  Tracks. 50 Files × 5s = ~4 Minuten bis die letzte BPM in der Queue
  steht. Wenn das zu lange wird können wir parallelisieren (BASS_FX
  kann mehrere Decode-Streams gleichzeitig analysieren, kostet Cores).

## Was NICHT geändert wurde

- `JustPlay.Analysis/AnalyzeAsync` ruft *nur* den BPM-Detector auf. Key
  + Energy haben Interface-Stubs aber keine Implementations — das war
  der `🟡 interface defined, no DSP implementation yet` Status den ich
  in der README so eingetragen habe.
- Vinyl-Animation läuft unverändert auf der konstanten 30°/s — der Vinyl
  reagiert NICHT auf BPM. Ob das gewünscht ist (Vinyl pulsiert auch im
  Takt) müssten wir separat entscheiden.
